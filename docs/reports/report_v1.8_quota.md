# v1.8：全局每日额度 + 单应用每日限额（已实现并在 vivo 真机验证）

- 设备：vivo V2527A（Android 16），serial `<device>`
- 版本：`com.aid.usageguard` 1.7（versionCode 14，DB v4），MD5 `5933d3b32878284bbbe25bc9eb9559ad`
- 原问题：此前只有「开关式默认限制」和只做提醒的「每日目标」，**没有基于时长的拦截**，也没有单应用限额。

## 一、实现内容

| 能力 | 规则 |
|---|---|
| **全局每日额度** | 今日总使用时长 ≥「每日目标」（现 300 分钟）且开关开启时：除**白名单**与**系统保护应用**（系统 UI/输入法/桌面等）外，所有应用一打开就被拦截，浮层提示「今日额度已用完」；停留在应用内超过额度也会在下一次 20s 巡检时拦截 |
| **单应用每日限额** | 给某应用设置每日 X 分钟后，该应用今日累计使用 ≥ X 即拦截，浮层提示「今日用量已超限」；**与全局是否超时无关**；**显式限额优先于白名单**（针对用户明确要求「单独限制这个 app」的场景） |
| 数据 | 新增 Room 表 `app_daily_limit`（DB v4，迁移保留全部数据）；全局额度复用 `dailyTargetMinutes` + 新增 `dailyBudgetEnforced` 开关 |
| 策略 | `domain/quota/QuotaPolicy`（纯函数，9 个单测）：系统保护 > 单应用限额 > 白名单 > 全局额度 |
| 拦截 | `GuardService` 内置实时计账（DB 基线 + 前台时长累计、跨日重置），窗口切换与 20s 巡检双通道判定 |
| UI | App 详情页「每日限额」卡（不限/15/30/60/90/120/180/240/自定义 1–1440，显示今日已用与剩余、超限红字）；应用列表「限额 X 分钟」徽章；设置页「每日使用额度」卡（今日已用/剩余 + 拦截开关）；首页显示额度剩余 |
| AI | 新工具 `set_app_daily_limit`（草案）、`set_daily_budget_enforced`（草案）、`get_quota_status`（只读查询），工具总数 30；额度/限额改动同样走「待确认操作」 |

## 二、真机验证

| 场景 | 结果 |
|---|---|
| 全局额度用尽（测试值：额度 1 分钟，今日已用 385 分钟；关闭默认限制以排除规则拦截） | 日志：`blocked=true rule=false quota=GLOBAL_BUDGET_EXCEEDED total=385/1m`；浮层「今日额度已用完 / 今天已经用满 1 分钟额度（已用 385 分钟）…」✅ |
| 单应用限额（微信，白名单应用，限额 1 分钟，今日已用 55 分钟） | 打开微信即被拦截，浮层「今日用量已超限 / 这个应用今天限额 1 分钟，已经用了 55 分钟」✅（证明：与总时长无关 + 限额优先于白名单） |
| App 详情页限额卡 | 「每日限额 / 不限时 → 点自定义输入 1 → 1 分钟 / 今天已用 55 分钟 · 今日剩余 0 分钟 / 红字：达到 1 分钟上限」；DB `app_daily_limit` 写入 `com.tencent.mm=1` ✅ |
| 清除限额 | 点「不限」→ 卡回「不限时」、DB 记录删除 ✅ |
| 设置页额度卡 | 「每日使用额度 / 今日已用 388 / 300 分钟 · 剩余 0 分钟 / 超出额度后拦截非白名单应用（开）」✅ |
| 数据库迁移 | v3 → v4，会话/记录/对话全部保留，新增 `app_daily_limit` 表 ✅ |
| 单元测试 | 26 个全部通过（含 QuotaPolicy 11 个：额度内放行、达额拦截、单应用优先、白名单/系统保护豁免、剩余不为负等） |

## 三、测试后状态还原

- 微信限额已清除（「不限」），全局额度恢复为 300 分钟，默认限制开启，额度拦截开启
- 测试中因 force-stop 导致无障碍服务被系统关闭，已重新绑定（日志确认 Bound services）
