# v1.8.1：修正限制语义（额度内全放行，超额后才只允许白名单）

- 设备：vivo V2527A（Android 16），versionCode 16，DB v4，MD5 `fdd3cf719b78e0e8cf997efdcd1707a6`
- 用户澄清：**额度没超过时，不在白名单的 App 也要能正常运行；白名单只是「额度用完后」的通行证**

## 一、问题

v1.8 之前「默认限制」是一个始终生效的开关：非白名单第三方应用**一打开就拦**，与额度无关，
导致「还没超额就被挡」，与用户本意不符。

## 二、修正：限制模式三选一（默认「超额后才限制」）

| 模式 | 行为 |
|---|---|
| **超额后才限制（默认）** | 额度内所有应用（含非白名单）都能正常用；今日总时长 ≥ 每日额度后，只有**白名单**（和系统保护应用）还能打开，其余应用拦截，浮层提示「今日额度已用完」 |
| 始终限制非白名单 | 旧行为：非白名单一打开就拦（与额度无关） |
| 只限制指定应用 | 只有手动标记受限的应用被拦 |

- **单应用每日限额**在任何模式下独立生效（超了只拦那个应用，与总额度无关；显式限额优先于白名单）。
- 系统保护应用（桌面/输入法/电话短信/设置等）永不拦截。
- 设置入口：设置 → 限制模式（三选一，带说明）；AI 也能改：`set_restriction_mode`（草案，需确认）。

## 三、真机验证（vivo）

| 场景 | 结果 |
|---|---|
| 额度内（临时额度 1000 分钟，今日 388）：打开知乎（非白名单） | `blocked=false rule=false mode=QUOTA_AFTER_BUDGET quota=NONE total=388/1000m` —— **额度内非白名单可正常使用** ✅ |
| 超额（临时额度 100 分钟，今日 388）：打开知乎 | 浮层「今日额度已用完：今天已经用满 100 分钟额度（已用 388 分钟）。除了允许名单里的应用，其他应用今天都不能再用了。」✅ |
| 超额时打开白名单应用（DeepSeek） | 正常进入前台，无拦截浮层 ✅ |
| 单应用限额（微信限额 1 分钟、今日已用 55 分钟，且在额度内） | 打开微信被拦「今日用量已超限」——独立于总额度、优先于白名单 ✅（v1.8 已验证） |
| 单元测试 | 26 个通过（QuotaPolicy 11 个：额度内放行/超额拦截/单应用优先/白名单与系统保护豁免等） |
